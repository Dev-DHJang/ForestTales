# 03. 기능과 UX

## 화면과 입력

- Android 가로 화면의 왼쪽 이동 영역과 오른쪽 행동 버튼을 기본 방향으로 삼는다.
- 터치 영역은 손가락으로 안정적으로 누를 수 있어야 하며 OS 제스처, 노치와 safe area를 침범하지 않는다.
- 멀티터치 이동·공격, 버튼 경계 이탈, 포커스 손실과 복귀 뒤 입력 고착이 없어야 한다.
- 구체 터치 크기, 배치 프리셋과 사용자 조정 범위는 실제 기기 검증 뒤 ADR로 확정한다.

## 프로토타입 흐름

    앱 실행 → 연습 또는 AI 대전 → 캐릭터·직업·장신구·경기장 선택
    → 전투 → 링아웃/복귀 또는 결과 → 재시도/선택 화면

실제 모드, 승리 조건과 콘텐츠 수량은 해당 Phase에서 승인한다. 성장·획득·인벤토리 저장을 선택 화면과 혼동하지 않는다.

## Camera2D와 HUD

- 카메라는 두 파이터와 위험 경계를 담고 최소·최대 줌 및 스무딩을 적용한다.
- 최대 줌아웃에서도 동물 종, 직업, 장신구와 공격 포즈가 읽혀야 한다.
- HUD는 전투 상태를 읽어 표현하며 피해, stock 또는 승패를 계산하지 않는다.
- 개발 오버레이는 상태, 공격 단계와 성능 정보를 릴리스 UI와 분리한다.

## Android 생명주기

- 중단·백그라운드 진입 시 오프라인 전투를 일시정지하고 입력과 오디오를 정리한다.
- 복귀 시 중복 진행 없이 명시적 재개 흐름을 제공한다.
- 포커스 손실 시 눌린 입력을 해제하고 safe area 변경을 다시 계산한다.
- 초기 Phase에는 저장되지 않은 매치 복원을 약속하지 않는다.

## 접근성

- 위험, 피격과 상태를 색상 하나에만 의존하지 않는다.
- 화면 흔들림, 번쩍임, hit-stop과 진동의 조절 가능성을 설계한다.
- 텍스트, 아이콘과 핵심 조작이 작은 화면과 손가락에 가려지지 않게 한다.
