# ForestTales 결정 기록

미정 제품 규칙을 ADR로 관리한다. 사용자 승인 없는 제안은 영구 구현 기준이 아니다.

## 상태

- proposed: 검토 중이며 교체 가능한 프로토타입 선택만 허용.
- accepted: 사용자가 승인해 번호순 제품 문서보다 우선하는 결정.
- superseded: 새 ADR로 대체된 결정.
- rejected: 구현 근거로 사용할 수 없는 결정.

## ADR-001: Phase 1 승리 방식과 링아웃 흐름 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 링아웃·복귀·결과 회귀를 구현하려면 최소 경기 종료 규칙이 필요하다.
- 결정: 각 파이터는 3 stock으로 시작하고 링아웃 때 1 stock을 잃은 뒤 짧은 무적과 함께 스폰으로 복귀한다. 0 stock이면 패배하며 Phase 1에는 제한 시간을 두지 않는다.
- 대안: 단판 링아웃, 체력 0 패배, 제한 시간과 동점 판정.
- 영향: stock HUD와 결과 이벤트가 필요하지만 영속 성장·보상은 만들지 않는다.
- 검증: 연속 링아웃, 동시 최종 링아웃과 복귀 중 재링아웃을 자동 검사한다.
- 대체/롤백: MatchRules 데이터로 수치와 방식이 교체 가능해야 한다.
- 승인 근거: 2026-09-06 사용자 응답에서 제안 규칙 전체 승인.

## ADR-002: Phase 1 피해·넉백·경직 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 공격 결과가 임시 수치라도 한 곳에서 결정되어야 전투 회귀를 만들 수 있다.
- 결정: 누적 피해율 방식으로 시작한다. 적중 시 피해율을 더하고 `base_knockback + damage_after_hit × growth`를 무게 보정해 넉백 속도를 구하며, 경직은 넉백 속도에 비례하되 상·하한을 둔다. 모든 계수는 CombatRules 데이터에 둔다.
- 대안: 고정 HP, 공격별 고정 넉백, 곡선 기반 공식.
- 영향: 높은 피해율일수록 링아웃 가능성이 커지고 정확한 계수는 플레이테스트 조정 대상이다.
- 검증: 동일 초기 상태·입력·tick의 동일 결과, 무게 순서, 피해 증가에 따른 단조 증가와 상·하한을 자동 검사한다.
- 대체/롤백: CombatMath 구현을 교체하고 AttackData·UI 이벤트 계약은 유지한다.
- 승인 근거: 2026-09-06 사용자 응답에서 누적 피해율 넉백 승인.

## ADR-003: Phase 1 공중 점프 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 점프 상태와 입력 회귀에 공중 점프 횟수 및 회복 시점이 필요하다.
- 결정: 기본 파이터는 지상 점프 후 공중 점프 1회를 가지며 권위 플랫폼에 착지하면 회복한다. 피격·넉백은 남은 횟수를 회복하지 않는다.
- 대안: 공중 점프 없음, 종/직업별 기본 횟수, 피격 후 회복.
- 영향: 기본 이동 상태에 남은 공중 점프 카운터가 추가되며 이후 CharacterStats가 횟수를 변경할 수 있다.
- 검증: 지상→공중 점프, 초과 입력 무시, 착지 회복과 피격 비회복을 자동 검사한다.
- 대체/롤백: 기본 횟수를 데이터로 바꾸고 의미 입력 ID는 유지한다.
- 승인 근거: 2026-09-06 사용자 응답에서 공중 점프 1회 승인.

## ADR-006: Phase 0 터치 입력 기준안

- 상태: proposed
- 날짜: 2026-09-06
- 적용 Phase: 0/1
- 배경: 멀티터치와 포커스 손실 회귀를 검증하려면 교체 가능한 초기 배치가 필요하다.
- 결정: Phase 0에서는 화면 하단 42%만 입력에 쓰고 왼쪽에 이동, 오른쪽에 행동을 둔다. 좌우 6.5%는 임시 safe edge로 입력에서 제외하며 영역 이탈은 이전 의미 입력을 해제한다.
- 대안: 가상 스틱, 자유 배치, 고정 이미지 버튼.
- 영향: 현재 비율은 플레이테스트용이며 safe area·최소 물리 크기·사용자 조정 범위를 확정하지 않는다.
- 검증: 에뮬레이터에서 다중 포인터와 이탈을 검사하고 실제 Android 기기에서 가림·도달성과 OS 제스처 충돌을 후속 확인한다.
- 대체/롤백: 입력 영역 테이블만 바꾸고 의미 입력 ID는 유지한다.

## ADR-007: Phase 0 성능 측정 기준안

- 상태: proposed
- 날짜: 2026-09-06
- 적용 Phase: 0
- 배경: 예산 확정 전에 재현 가능한 기준 장면과 측정 항목이 필요하다.
- 결정: 1280×720 논리 해상도, GL Compatibility, 60 FPS 후보를 시작점으로 삼고 프레임 시간·메모리·draw call을 기록한다.
- 대안: Forward+ 또는 Mobile renderer, 30 FPS 기준, 다른 논리 해상도.
- 영향: 목표 수치와 기준 기기는 아직 승인되지 않았으며 실제 기기 측정 뒤 조정한다.
- 검증: 기준 기기에서 10분 실행 후 프레임 시간 분포, 메모리와 발열 저하를 기록한다.
- 대체/롤백: ProjectSettings 렌더러와 논리 해상도를 변경하고 장면 계약은 유지한다.

## ADR-011: Android 애플리케이션 식별자·지원 ABI 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 0
- 배경: debug APK 생성에는 유효한 package ID와 ABI 선택이 필요하다.
- 결정: package ID는 `com.foresttales.welllbeing`, ABI는 실제 기기용 arm64-v8a와 로컬 에뮬레이터용 x86_64를 사용한다. 최소 Android 버전은 제품 기준인 Android 10이다. 향후 물리 기기 기준대상은 Galaxy S23 Ultra이며 당분간 에뮬레이터를 사용한다.
- 대안: 사용자가 소유한 역도메인 package ID, arm64-v8a 단일 ABI.
- 영향: 스토어 등록 또는 외부 배포 전에 소유권 있는 package ID로 확정해야 한다.
- 검증: debug export, 에뮬레이터 설치·실행, 최종 기준 기기의 arm64 설치를 확인한다.
- 대체/롤백: 공개 배포 전 export preset의 식별자와 ABI를 교체한다.
- 승인 근거: 2026-09-06 사용자 응답에서 package ID 철자와 Galaxy S23 Ultra 기준대상, 당분간 에뮬레이터 사용을 지정.
