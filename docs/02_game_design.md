# 02. 게임 디자인

## 전투 공간

- 전투는 X/Y 좌표만 사용하는 측면 2D 공간이다.
- 점프 가능한 권위 플랫폼, 두 파이터의 스폰 지점과 링아웃 영역을 둔다.
- Camera2D는 파이터와 주요 위험 경계를 함께 보여주며 위치·줌 변화가 입력 판단을 방해하지 않게 한다.

## 의미 입력

- 최소 의미 동작은 좌우 이동, 점프, 대시, 약공격, 강공격과 특수 공격이다.
- 터치 UI와 데스크톱 어댑터는 같은 의미 명령을 전투에 전달한다.
- 방어, 회피, 잡기, 궁극기와 전용 장신구 입력은 관련 ADR과 Phase가 승인되기 전 만들지 않는다.

## 전투 규칙

공격 흐름은 공격 시작, startup, active, 충돌 해결, hitbox 종료, recovery 순서다.

- AttackData가 단계 시간, 피해, 넉백, hitbox와 재타격 조건을 소유한다.
- 상태 머신이 전이, 행동 잠금과 취소 가능 여부를 결정한다.
- 최소 상태 후보는 대기, 달리기, 점프, 낙하, 대시, 공격, 피격 경직, 넉백과 링아웃이다.
- 단발 공격은 한 활성화에서 같은 대상을 한 번만 맞히며 자가 타격을 허용하지 않는다.
- 보이는 몸·발톱·무기, 애니메이션 프레임과 VFX는 판정의 권위가 아니다.
- 정확한 피해·넉백·경직 공식과 최종 승리 방식은 proposed ADR이며, 프로토타입 임시값은 교체 가능해야 한다.

## 캐릭터·직업·장신구

- CharacterData는 기본 전투 정체성, 능력치, 기술, 패시브, 태그와 직업 트리 참조를 가진다.
- JobData는 단순 수치 상승을 넘어 이동, 기술 슬롯, 패시브, 취소 규칙과 태그를 변경할 수 있다.
- AccessoryData는 매치 단위의 능력·기술·조건 효과를 태그 기반으로 조합한다.
- 공용 컨트롤러에 캐릭터·직업·장신구 이름별 분기를 넣지 않는다.

## 경기장

StageData가 권위 있는 플랫폼, 스폰과 링아웃 경계를 정의한다. 배경, 패럴랙스, 소품과 VFX는 별도 시각 레이어에 있으며 충돌이나 승패를 바꾸지 않는다.
